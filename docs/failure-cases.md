# 失败案例分析

> 这一节记录开发过程中真实遇到的坑：现象、定位过程、最终修法。
> 写设计报告时可以直接引用，答辩时讲这些比讲"我做完了"有说服力得多。

每个案例都标注了**发现方式**——这比修复本身更能体现工程能力。

---

## 案例 1：符号名不是器件型号

**现象**
真实模型生成的连接关系里，生成原理图时警告：

```
[WARN] U1 的符号 MCU_Microchip_ATmega:ATmega328P-PU 库里没有，最接近的是 ...:ATmega328P-P
[WARN] 网络 VCC 的引脚 U1.7 未在图上找到   （×20 条）
```

对账结果 42 处不一致——整个 MCU 像是消失了。

**原因**
模型把**芯片型号**当成了**KiCad 符号名**。
`ATmega328P-PU` 是买得到的器件型号，而 KiCad 8 符号库里叫 `ATmega328P-P`（P 表示 DIP 封装）。
符号找不到 → 该器件被整体跳过 → 它的所有引脚都不存在 → 所有相关网络断裂。

**修复**
`src/sch_writer.py` 增加 `fix_symbols()`：用 `difflib` 在库文件里做模糊匹配，
命中则自动改名并在日志中说明；命中不了则报错。

```
[修正] U1 的符号 ATmega328P-PU -> ATmega328P-P（库里真实的名字）
```

**教训**
LLM 对"名字"极不敏感，它不知道自己要写的是**库里的标识符**。
凡是让模型输出标识符的地方，都必须有**存在性校验 + 自动纠错**。

## 案例 2：`extends` 继承导致符号"空心"

**现象**
即使符号名正确，解析出的引脚数是 **0**。

**原因**
KiCad 库里大量符号使用继承：

```
(symbol "ATmega328P-P"
  (extends "ATmega48PV-10P")   ← 自己没有引脚定义
  ...
)
```

`.kicad_sch` 里必须存**拍平后**的完整定义，不能保留 `extends`。

**修复**
递归取父符号定义，再把顶层名和**子单元名**一起改名：

```
(symbol "ATmega48PV-10P_1_1"  →  (symbol "ATmega328P-P_1_1"
```

只改顶层名不改子单元名，KiCad 仍然加载失败——因为单元归属对不上。

**教训**
"看起来拿到了符号"和"拿到了可用的符号"是两件事。
验证方式：拿到的引脚数是否等于数据手册的引脚数（28）。

## 案例 3：`.kicad_sch` 格式不兼容，KiCad 只报一句"加载失败"

**现象**

```
$ kicad-cli sch export netlist --output out.net board.kicad_sch
加载原理图文件失败
```

没有任何行号、没有字段名，只有这一句。

**定位过程**
本机装了 KiCad 8，自带官方示例工程（`share/kicad/demos/`）。
直接把我的文件和一个真实文件逐字段比对，才发现四处差异：

| 项目 | 我写的（错） | 实际要求 |
|---|---|---|
| 格式版本 | `20231120` | `20230819`（8.0 的版本号） |
| 生成器 | `(generator "eeschema")` 带引号 | `(generator eeschema)` 不带引号 |
| uuid | `(uuid "xxx")` 带引号 | `(uuid xxx)` **不带引号** |
| 隐藏属性 | `(hide yes)` | 裸 `hide` |
| 线型 | `(type default)` | `(type solid)` |

`(hide yes)` 是 KiCad 9 的写法，8.0 不认识，直接判为非法。

**教训**
闭源格式报错信息极差时，**比"读文档"更可靠的是"找一个能跑的真文件 diff"**。
本机安装目录里的 demo 就是最好的参考实现。

## 案例 4：固定网格布局把整块板短路了

**现象**
对账显示某个网络"期望 2 引脚，图上 **69** 引脚"——几乎所有引脚被并成一个网络。

**原因**
两个叠加的问题：

1. **布局有碰撞**：原本用 38.1mm 固定网格摆放，而 ATmega328P 符号本身就有 35mm 宽，
   相邻器件的引脚短接线互相压住 → KiCad 认为导通。
2. **标签锚点重合**：不同引脚算出的标签坐标完全相同，两个网络的标签叠在一点 → 直接合并。

**修复**
1. 布局改为**按符号真实外框尺寸**自适应的货架式排版（`build_schematic` 第一遍量尺寸，第二遍摆放）；
2. 增加**全局锚点去重**：锚点重复时自动把这段引线拉长 2.54mm，把标签岔开。

**教训**
"电气连接"在 KiCad 里是**几何相等**，不是逻辑声明。
生成图纸时，任何坐标碰撞都会变成真实的短路。布局算法不是美化，是正确性的一部分。

## 案例 5：模型把同一个引脚塞进两个网络

**现象**
校验器报：

```
[FAIL] 引脚 C1.2 同时出现在网络 GND 和 XTAL2 —— 一个引脚只能属于一个网络
```

**原因**
晶振负载电容应该是一端接 XTAL、另一端接 GND。
模型把两颗电容的两端搞混了，写成"C1.2 既在 GND 又在 XTAL2"。
这在物理上不可能：一个引脚只能属于一个网络。

**修复（三层）**
1. **校验层**：`validate()` 增加"引脚重复归属"检查，判为**错误**而非警告；
2. **Prompt 层**：把每个器件在 KiCad 库里的**真实可用引脚清单**（`available_pins`）
   直接塞进 Prompt，模型不用猜引脚号；
3. **重试层**：校验失败自动把错误清单回喂给模型，最多 3 轮；
4. **修复层**：多轮仍不收敛时，按规则自动修复（优先保留电源网络），
   **每一处修改都打印出来**，绝不静默改数据。

**效果**
错误数 44 → 26 → 4 → **0**（连续两轮全部一致）。

**教训**
> 与其指望模型一次做对，不如假设它一定会错，然后设计"发现—回喂—修复"的闭环。

这正是课程要求的「反馈闭环」的真实价值：**不是为了好看，是因为不这么做根本跑不通。**

## 汇总

| 案例 | 层次 | 发现方式 | 关键修复 |
|---|---|---|---|
| 1 符号名错 | 数据 | 生成警告 + 对账差异 | 模糊匹配自动纠错 |
| 2 继承空心 | 数据 | 引脚数 = 0 | 递归拍平 + 子单元改名 |
| 3 格式不兼容 | 文件 | kicad-cli 报错 | 与官方 demo 逐字段 diff |
| 4 布局短路 | 几何 | 网络引脚数暴涨 | 自适应排版 + 锚点去重 |
| 5 引脚重复归属 | 数据 | 校验器拦截 | 校验 + Prompt + 重试 + 修复 |

**五个案例里有四个源于同一个根因：模型不懂它输出的是"标识符"和"坐标"，而不是自然语言。**
工程上能做的，是在它后面架设校验与修复，而不是要求它别犯错。
