# 全自动模式：不用手动复制粘贴

人工中转模式（`一键运行.bat`）需要你把 Prompt 复制到网页、再把回答存回文件。
**要摆脱这个动作，只有一个前提：程序能直接连上一个模型接口。**

好消息是，接口有三种来源，而本项目只认 **OpenAI 兼容格式**，
所以换来源时**只改 `.env` 里两行，代码一个字都不用动**。

---

## 方案对比

| 方案 | 花多久 | 花钱 | 效果 | 推荐度 |
|---|---|---|---|---|
| **① 课程统一密钥** | 问助教，等回复 | 免费 | 最好 | ★★★★★ |
| **② 本机 Ollama 跑小模型** | 30–60 分钟 | 免费 | 中等，需重试兜底 | ★★★ |
| **③ 自己注册云平台** | 10 分钟 | 几块钱 | 好 | ★★★★ |
| ④ 山大云 GPU 自部署 | 3 小时+ | 免费 | 好 | ★ |

## 方案 ①：课程密钥（最优）

拿到后改 `.env`：

```
LLM_API_KEY=sk-xxxxxxxx
LLM_BASE_URL=https://课程给的地址/v1
LLM_MODEL=课程指定的模型名
```

然后双击 **`一键全自动.bat`**，输入需求，等十几秒，结果在 `out\auto\`。

---

## 方案 ②：本机 Ollama（完全离线，不要密钥）

**它能用，是因为 Ollama 提供了 OpenAI 兼容接口**，地址是 `http://localhost:11434/v1`。

### 步骤

1. 下载安装 Ollama：https://ollama.com/download
2. 装完打开命令行（或 Ollama 自带的终端），拉一个模型：

```
ollama pull qwen2.5:7b
```

> 约 4.7 GB。内存 16G 以上跑 7b 比较稳；只有 8G 内存就用 `qwen2.5:3b`（约 2 GB，但出错率明显更高）。

3. 确认 Ollama 在跑：浏览器打开 `http://localhost:11434` ，看到 `Ollama is running` 即可。

4. 改 `.env`：

```
LLM_API_KEY=ollama
LLM_BASE_URL=http://localhost:11434/v1
LLM_MODEL=qwen2.5:7b
```

5. 双击 **`一键全自动.bat`**。

### 要注意的

- **小模型容易输出不规范的 JSON。** `src/llm.py` 里有自动重试（把报错回喂给模型），
  一般能救回来，但可能要多等一两轮。
- **引脚容易漏。** 7B 模型生成 28 引脚 MCU 的连接关系时可能少写几条。
  校验器会报「引脚未接入」，但对账仍会通过（因为图是按它给的 JSON 画的）。
  **答辩时这点要主动说明**，别装作完美。
- 别用 3b 以下的模型，基本没法用。

## 方案 ③：自己注册云平台

国内几家都提供 OpenAI 兼容接口，注册后在控制台生成密钥，价格按量计，跑这个作业通常几块钱。

| 平台 | LLM_BASE_URL | LLM_MODEL 示例 |
|---|---|---|
| 深度求索 | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 阿里百炼 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |

## 自检

配好后先双击 `一键全自动.bat`，它会**先跑一次连通性检查**再开始干活：

```
检查模型接口 ……
  BASE_URL : http://localhost:11434/v1
  MODEL    : qwen2.5:7b
  API_KEY  : 已填写
[ OK ] 接口连通，模型返回：{'ok': True}
```

看到 `[ OK ]` 就说明通了。失败时它会直接告诉你可能的原因。

## 三种模式的关系

```
一键全自动.bat   ← 有接口时用，全自动，推荐
一键运行.bat     ← 没接口时用，人工中转，模型仍真实参与
一键改参数.bat   ← 任何时候都能用（改设计不需要模型）
```

三者共用同一套下游代码（校验、出图、对账），所以**换成全自动不会改变结果的正确性判断标准**。
